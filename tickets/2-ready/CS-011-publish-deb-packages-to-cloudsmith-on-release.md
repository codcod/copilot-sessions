# CS-011 — Publish .deb packages to Cloudsmith on release

## Outcome

After this ships, `sudo apt install copilot-sessions` (or `apt upgrade`) from the Cloudsmith
repository gets the latest tagged release on both amd64 and arm64, instead of the one-off
CS-005 test build (`0.0.0~cs005.d72b817`, amd64 only) that is there today.

## Description

The README documents an apt install from the Cloudsmith repository `codcod/copilot-sessions`
(setup script, or key + `sources.list.d` entry by hand). Both were verified on 2026-11-09 in an
`ubuntu:26.04` container: on amd64 they install the CS-005 test package; on arm64 `apt install`
fails with `Unable to locate package`. Nothing in the release process publishes there —
CS-008 scoped `.deb`/Cloudsmith out on purpose (its decision 6, "only `GITHUB_TOKEN`"), and the
CS-005 review (F5) noted that a release-automation ticket would own the apt path.

Model it on pickle's release (`codcod/pickle`: `.github/workflows/release.yml` step *Publish
.deb to Cloudsmith*, `.goreleaser.yaml` `nfpms`, RELEASING.md *Debian/Ubuntu packages*):

- **`.goreleaser.yaml`** gains an `nfpms` entry: `formats: [deb]`, package name
  `copilot-sessions`, `bindir: /usr/bin`, `file_name_template:
  "{{ .ProjectName }}_{{ .Version }}_{{ .Arch }}"`, vendor/maintainer/homepage/license/description.
  The `.deb` files are also attached to the GitHub release (goreleaser does this by default).
  The package also installs bash/zsh/fish completions under `/usr/share/…`, generated by a
  goreleaser `before` hook (decided 2026-11-09).
- **`.github/workflows/release.yml`** gains a last step after goreleaser that pushes
  `dist/*.deb` with `cloudsmith push deb codcod/copilot-sessions/any-distro/any-version <f>
  --republish` (pinned `cloudsmith-cli==1.30.0` via `pipx`). It soft-fails like pickle's:
  missing `CLOUDSMITH_API_KEY`, a prerelease tag (contains `-`), no `.deb`, or a failed CLI
  install each exit 0 with a `::warning::` and a job-summary line; every package is tried so one
  failed push never strands the other architecture.
- **Secret** `CLOUDSMITH_API_KEY` on `codcod/copilot-sessions` (one-time, human; prefer a service
  account scoped to this Cloudsmith repo).
- **RELEASING.md** gets a *Debian/Ubuntu packages* section: secret, soft-fail rules, re-pushing an
  old tag by hand (`gh release download … -p '*.deb'` + push loop), retention (deferred, as in
  pickle).
- **Cleanup** (human, after the first real release): delete the CS-005 test package from
  Cloudsmith. Its version sorts below any real one, so it never shadows an upgrade; this is
  hygiene only.
- **README** apt section (written 2026-11-09, still uncommitted on `main` at refinement) ships
  with this ticket, so the docs and the packages arrive together.

No tag or GitHub release exists yet (checked 2026-11-09), so the first Cloudsmith push will be
the first release, `v0.1.0` or whatever the human tags. CS-009/CS-010 will add darwin/windows
builds later; goreleaser's `nfpms` only packages linux builds, so they need no change here.

Facts checked on 2026-11-09 that the plan must honour: Cloudsmith serves `any-distro` packages
under real distro paths (`deb/ubuntu resolute`, `deb/debian bookworm`), and
`deb/any-distro any-version` has no `Release` file — the README already uses
`$ID $VERSION_CODENAME`. The binary is static (`CGO_ENABLED=0`), so one package per
architecture serves every Debian/Ubuntu release.

Soft couplings: CS-008 (release process this extends); CS-005 (the test package and F5 note).
The README's apt section is accurate only once this ships.

### Confirmed design decisions (do not deviate without asking)

1. **Copy pickle's mechanism, not invent one.** `nfpms` in `.goreleaser.yaml` builds the
   packages; a final, soft-failing workflow step pushes them with the `cloudsmith` CLI. Reference:
   `codcod/pickle` `.goreleaser.yaml`, `.github/workflows/release.yml` (*Publish .deb to
   Cloudsmith*), `RELEASING.md` (*Debian/Ubuntu packages*).
2. **One channel: `codcod/copilot-sessions/any-distro/any-version`.** The binary is static
   (`CGO_ENABLED=0`), so one package per architecture serves every Debian/Ubuntu release.
   Clients reach it through `deb/$ID $VERSION_CODENAME` (README); `deb/any-distro any-version`
   has no index.
3. **Package `copilot-sessions`, binary in `/usr/bin`, both `amd64` and `arm64`.** File names
   `copilot-sessions_<version>_<arch>.deb`, attached to the GitHub release as well.
4. **Ship completions.** A `before` hook generates `completions/copilot-sessions.bash`,
   `completions/_copilot-sessions` and `completions/copilot-sessions.fish` via
   `go run ./cmd/copilot-sessions completion <shell>`; `completions/` is gitignored. Installed to
   `/usr/share/bash-completion/completions/copilot-sessions`,
   `/usr/share/zsh/vendor-completions/_copilot-sessions`,
   `/usr/share/fish/vendor_completions.d/copilot-sessions.fish`.
5. **The Cloudsmith step never fails the release.** `continue-on-error: true`, and missing
   `CLOUDSMITH_API_KEY`, a prerelease tag (contains `-`), no `dist/*.deb`, or a failed CLI install
   each exit 0 with a `::warning::` and a `$GITHUB_STEP_SUMMARY` line. Every `.deb` is tried; any
   failures are named in one "publish incomplete" warning.
6. **Prereleases are not pushed.** One channel reaches every `apt upgrade`.
7. **`cloudsmith-cli` pinned to `1.30.0`**, installed with `pipx`; push uses `--republish`.
8. **Secrets: `GITHUB_TOKEN` + `CLOUDSMITH_API_KEY` only.** The key is set once by the human
   (`gh secret set CLOUDSMITH_API_KEY -R codcod/copilot-sessions`), preferably a Cloudsmith
   service account scoped to this repository. The agent never handles the key.
9. **Retention deferred**, as in pickle: documented, not applied.
10. **Old test package removed by hand** after the first real release is on Cloudsmith; the
    agent does not touch Cloudsmith.

### Acceptance test

From the repo root on the feature branch:

1. `just lint && just test && just dist-check && actionlint .github/workflows/*.yml` — all clean.
2. `just dist-snapshot`, then `ls dist/*.deb` lists exactly
   `copilot-sessions_<snapshot-version>_amd64.deb` and `…_arm64.deb`; `git status --porcelain`
   shows no `completions/` entry (gitignored).
3. Install each package in a fresh container of its own architecture:
   ```sh
   for arch in amd64 arm64; do
     docker run --rm --platform linux/$arch -v "$PWD/dist:/dist:ro" ubuntu:26.04 bash -euc "
       export DEBIAN_FRONTEND=noninteractive
       apt-get update -qq && apt-get install -y -qq /dist/copilot-sessions_*_$arch.deb >/dev/null
       dpkg -L copilot-sessions | grep -E '/usr/bin/copilot-sessions$|bash-completion/completions/copilot-sessions$|vendor-completions/_copilot-sessions$|vendor_completions.d/copilot-sessions.fish$' | wc -l | grep -qx 4
       head -1 /usr/share/zsh/vendor-completions/_copilot-sessions | grep -qx '#compdef copilot-sessions'
       copilot-sessions --version
       copilot-sessions list
       apt-get remove -y -qq copilot-sessions >/dev/null && ! command -v copilot-sessions
       echo $arch OK"
   done
   ```
   Expected: `amd64 OK` and `arm64 OK`; `--version` prints the snapshot version.
4. Soft-fail paths of the Cloudsmith step, extracted from the workflow and run with no key:
   ```sh
   docker run --rm -v "$PWD:/w" -w /w mikefarah/yq \
     '.jobs.goreleaser.steps[] | select(.name == "Publish .deb to Cloudsmith") | .run' \
     .github/workflows/release.yml > "$TMPDIR/cs-step.sh"
   S=$(mktemp); GITHUB_STEP_SUMMARY=$S CLOUDSMITH_API_KEY= TAG=v0.1.0 bash "$TMPDIR/cs-step.sh"; echo "exit=$?"; cat "$S"
   S=$(mktemp); GITHUB_STEP_SUMMARY=$S CLOUDSMITH_API_KEY=x TAG=v0.1.0-rc.1 bash "$TMPDIR/cs-step.sh"; echo "exit=$?"; cat "$S"
   ```
   Expected: both `exit=0`; first warns `CLOUDSMITH_API_KEY is not set`, second
   `v0.1.0-rc.1 is a prerelease`; each summary file has the `No .deb published` heading.
5. The real push is verified by the human at the first release (Finish, post-merge steps):
   the README's manual apt steps in `ubuntu:26.04` on both `--platform linux/amd64` and
   `linux/arm64` install the tagged version.
