# Releasing copilot-sessions

Releases are built by [goreleaser](https://goreleaser.com) from a `vX.Y.Z` tag. Each release
has `copilot-sessions_X.Y.Z_<os>_<arch>.tar.gz` for `linux` and `darwin`,
`copilot-sessions_X.Y.Z_windows_<arch>.zip` (`<arch>` is `amd64` or `arm64`), two Debian packages,
`copilot-sessions_X.Y.Z_amd64.deb` and `copilot-sessions_X.Y.Z_arm64.deb`, plus
`checksums.txt`. The packages are also pushed to the Cloudsmith apt repository
`codcod/copilot-sessions` (see *Debian/Ubuntu packages* below), which needs one secret,
`CLOUDSMITH_API_KEY`. Everything else uses `GITHUB_TOKEN`.

## Cut a release

1. Optional: run `pickle changelog check` to list shipped tickets missing from `[Unreleased]`.
2. In [`CHANGELOG.md`](CHANGELOG.md), retitle `[Unreleased]` to `[X.Y.Z] - YYYY-MM-DD`, add a
   fresh empty `[Unreleased]` above it, and fix the link references at the bottom:
   ```
   [Unreleased]: https://github.com/codcod/copilot-sessions/compare/vX.Y.Z...HEAD
   [X.Y.Z]: https://github.com/codcod/copilot-sessions/releases/tag/vX.Y.Z
   ```
   Commit it, so the tag contains the changelog.
3. Tag and push. The [`release`](.github/workflows/release.yml) workflow does the rest:
   ```sh
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

## Re-run a release

Actions → release → Run workflow, with an existing tag. `mode: replace` overwrites the assets
that are already there. The re-run also reaches the Cloudsmith step, so with
`CLOUDSMITH_API_KEY` set it re-pushes the rebuilt `.deb` files (`--republish`).

## Debian/Ubuntu packages (Cloudsmith)

goreleaser's `nfpms` section builds the two `.deb` files: the binary in `/usr/bin` plus bash,
zsh and fish completions, generated by a `before` hook into the gitignored `completions/`.
The last step of the release workflow, *Publish .deb to Cloudsmith*, then pushes them to
`codcod/copilot-sessions`, distribution `any-distro/any-version`. The binary is static, so one
package per architecture serves every Debian and Ubuntu release. Cloudsmith signs and serves
the apt index under each real distribution path (`deb/ubuntu resolute`, `deb/debian
bookworm`); the README's install steps use those.

- **Secret.** `CLOUDSMITH_API_KEY` is a Cloudsmith API key, stored as a repository secret:
  `gh secret set CLOUDSMITH_API_KEY -R codcod/copilot-sessions`. Prefer a service account's key
  with write access to `codcod/copilot-sessions` only over a personal key, so a leak reaches
  one repository.
- **Soft-fail.** The step never fails the release. It exits 0 with a `::warning::` annotation
  and a job-summary line, *No .deb published to Cloudsmith for vX.Y.Z*, when the secret is
  missing, the tag is a prerelease (contains `-`), there is no `dist/*.deb`, or the CLI install
  fails. A failed push does not stop the others: the step tries every package, then warns
  *Cloudsmith publish incomplete for vX.Y.Z* and names the ones that failed. Prereleases are
  skipped on purpose: there is one channel, and anything pushed to it reaches `apt upgrade`.
- **Re-pushing a tag** whose packages did not reach Cloudsmith. Do it by hand, with the
  `cloudsmith` CLI installed (`pipx install cloudsmith-cli==1.30.0`, the version the workflow
  pins) and `CLOUDSMITH_API_KEY` exported:

  ```sh
  D=$(mktemp -d)
  gh release download vX.Y.Z -R codcod/copilot-sessions -p '*.deb' -D "$D"
  for f in "$D"/*.deb; do
    cloudsmith push deb codcod/copilot-sessions/any-distro/any-version "$f" --republish
  done
  ```

  `cloudsmith push deb` takes one file per call, hence the loop. `--republish` replaces a
  version that is already there, so the block is safe to repeat.
- **Retention.** *Not applied yet*, so the repository keeps every version. The intended rule
  keeps the latest 5 versions (10 packages across two architectures), set once on the
  repository with a `PATCH` of `{"retention_enabled": true, "retention_count_limit": 10,
  "retention_group_by_name": true, "retention_days_limit": 0}` to
  `https://api.cloudsmith.io/v1/repos/codcod/copilot-sessions/retention/`.
- **The old test package.** `0.0.0~cs005.d72b817` (amd64) was pushed by hand during CS-005.
  It sorts below every real version, so it never shadows an upgrade. Delete it once the first
  release is on Cloudsmith.

## Validate locally

```sh
just dist-check      # goreleaser check
just dist-snapshot   # unpublished snapshot build into dist/ (tarballs and .deb files)
```

## Versions

goreleaser stamps the version without the `v` (`0.1.0`). A `go install` build has no ldflags
and reports the module version (`v0.1.0`):

```sh
go install github.com/codcod/copilot-sessions/cmd/copilot-sessions@vX.Y.Z
```
