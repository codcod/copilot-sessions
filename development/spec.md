# Spec: `copilot-sessions` in Go

## 1. Goal

Rewrite the Python script `~/.local/bin/copilot-sessions` as a Go program. The
program lists, deletes, backs up and restores GitHub Copilot CLI sessions.

The Go version keeps the flags, aliases and backup format of the Python
version, and restores its archives (and the script restores Go's). Where
idiomatic Go and the script's behaviour or output disagree, idiomatic Go wins;
section 11 lists every such difference. When this spec is unclear, it is the
spec that gets clarified, not the script that decides.

The program runs on Linux (WSL). It reads `/proc` for process detection.

## 2. Technical requirements

- Go 1.27 or later. One module, one binary named `copilot-sessions`.
- CLI framework: `github.com/spf13/cobra`.
- SQLite: choose the driver. Prefer `modernc.org/sqlite` (no CGO) unless you
  have a reason to use another. The driver must support the online backup API
  or `VACUUM INTO`, and must read WAL-mode databases.
- Use the standard library for everything else: `archive/tar`, `compress/gzip`,
  `encoding/json`, `os`, `path/filepath`, `time`.
- Install target: `~/.local/bin/copilot-sessions`. It replaces the Python
  script. Add a `Makefile` or `justfile` with `build`, `test` and `install`
  targets.
- Zsh completion is generated by the binary (section 8). It replaces the
  hand-written file `~/.zsh/completions/_copilot-sessions`.

## 3. Environment and paths

| Name | Default | Purpose |
|------|---------|---------|
| `COPILOT_HOME` | `~/.copilot` | Copilot data directory |
| `COPILOT_BACKUP_DIR` | `~/.copilot-backups` | Backup directory |

Paths inside `COPILOT_HOME`:

| Path | Content |
|------|---------|
| `session-state/<uuid>/` | One directory per session |
| `session-state/<uuid>/workspace.yaml` | Session metadata (section 4.1) |
| `session-state/<uuid>/events.jsonl` | Event log, one JSON object per line; can be missing |
| `session-state/<uuid>/inuse.<pid>.lock` | Exists while process `<pid>` uses the session |
| `session-state/.session-operation-locks/` | Copilot lock files. This is **not** a session. |
| `session-store.db` | SQLite index (WAL mode; `-wal` and `-shm` files exist next to it) |
| `open-sessions-state.json` | Object keyed by session ID: `{ "<id>": { "working": bool, ... } }` |
| `sidebar-sessions-state/*.json` | Objects with a `"sessionIds": [ ... ]` array |

Rule: a session directory is any **directory** in `session-state/` whose name
does not start with `.`. Ignore all hidden entries everywhere.

## 4. Data model

### 4.1 Reading a session

For each session directory, parse `workspace.yaml` line by line. Do not use a
YAML library. A line that does not start with a space and contains `:` gives
`key = text before the first ':'` and `value = text after it`, both trimmed.

Example:

```yaml
id: 3684801c-9e90-4431-bb66-fda080b6dd9e
cwd: /mnt/c/Users/x/projects/optimizr
name: Create Copilot Session Manager     # missing for sessions without a prompt
created_at: 2026-11-06T05:20:49.652Z
updated_at: 2026-11-06T05:20:49.668Z
```

Session fields:

| Field | Source |
|-------|--------|
| `id` | directory name |
| `name` | `name`, else DB `sessions.summary`, else `""` |
| `cwd` | `cwd`, else DB `sessions.cwd`, else `""` |
| `updated` | `updated_at`, else `created_at`, else directory mtime |
| `dir` | directory path; nil for DB-only sessions |

Timestamps are ISO 8601, sometimes with `Z`, sometimes quoted. Strip quotes
before parsing. A timestamp without a zone is UTC.

Also read `SELECT id, summary, cwd, created_at, updated_at FROM sessions`.
DB rows without a directory become **DB-only sessions** with `dir = nil`.
For directory sessions, the DB only fills empty fields.

### 4.2 Status

| Status | Rule |
|--------|------|
| `ongoing` | at least one `inuse.<pid>.lock` exists and `/proc/<pid>/cmdline` contains the bytes `copilot` |
| `stale` | at least one `inuse.*.lock` exists, but none passes the `ongoing` check |
| `closed` | no `inuse.*.lock` file exists, or the session is DB-only |

`busy` is `open-sessions-state.json[id].working == true`. It is shown only
for `ongoing` sessions.

**Current session.** Build the set of ancestor PIDs of the running process:
start at `os.Getpid()` and follow the parent PID up to PID 1. The parent PID
is field 2 after the **last** `)` in `/proc/<pid>/stat`. A session is
`current` if one of its lock PIDs is in that set. This is the Copilot session
that runs the command.

### 4.3 Empty sessions

A session is **empty** if both of these are true:

- `session_id` does not appear in DB table `turns`.
- `events.jsonl` is missing, or no line contains the substring
  `"type":"user.message"`. Stream the file line by line; it can be several MB.

Empty sessions come from Copilot launches that ended before the first prompt.
They have no title. Compute this only when `--empty` is used.

### 4.4 Size

Size is the sum of `lstat` sizes of all regular files under the session
directory. It is 0 for DB-only sessions. Compute it only when it is printed
(see `-q`).

## 5. Date and filter parsing

### 5.1 DATE values

Parsing is case-insensitive and trims spaces. All dates use the **local
timezone**.

| Input | Result |
|-------|--------|
| `YYYY-MM-DD` | that date |
| `today` | local today |
| `yesterday` | today Ôłĺ 1 day |
| `Nd` | today Ôłĺ N days |
| `Nw` | today Ôłĺ 7┬ĚN days |
| `Nm` | today Ôłĺ N calendar months; if the day does not exist, use the last day of that month (2026-03-31 Ôłĺ 1m = 2026-02-28) |

Invalid input is a usage error (exit 2):
`invalid date '<v>'; use YYYY-MM-DD, today, yesterday, Nd, Nw or Nm`.

### 5.2 Filters (`list` and `clean`)

All filters combine with **AND**, including ID prefixes.

| Flag | Meaning |
|------|---------|
| `ID...` (positional) | full ID or unique prefix |
| `-u, --until DATE` | local date of `updated` ÔëĄ DATE |
| `--since DATE` | local date of `updated` Ôëą DATE |
| `-s, --status LIST` | comma-separated subset of `ongoing,stale,closed` |
| `-c, --cwd PATH` | `cwd` equals PATH or is below it. Expand `~`, make the path absolute, clean it. `/a/b` matches `/a/b` and `/a/b/c`, not `/a/bc`. |
| `-g, --grep TEXT` | `name` contains TEXT, case-insensitive |
| `-e, --empty` | session is empty (4.3) |

Sessions with an unknown `updated` never match `--until` or `--since`.

ID prefix errors (exit 1):

- No match: `no session matches ID '<p>'`
- More than one match: `ID '<p>' is ambiguous: <up to 5 sorted IDs, comma+space separated>`

Invalid `--status` value is a usage error (exit 2):
`invalid status '<v>'; use a comma-separated list of ongoing, stale, closed`.

## 6. Commands

Global: `-h/--help`. A bare `copilot-sessions` prints the root help to stdout
and exits 0. Errors go to stderr as `error: <message>`, with exit code 1.
Usage errors use exit code 2: bad flag values, unknown flags, wrong argument
counts, the flag-combination checks under each command's **Validation**, and
unknown commands (Cobra's message, with `Did you mean this?` suggestions).
`help <unknown>` is Cobra's: `Unknown help topic` and the root usage, exit 0.
Ctrl-C prints `\nAborted.` to stderr (no `error:` line) and exits with 130
(CS-013):

- Ctrl-C at a prompt (`[y/N]`, `Restore which backup?`) aborts at once.
- Cancellation is honoured up to each command's irreversible step: deleting
  sessions (`clean`), swapping the restored items in (`restore`) and removing old
  backups (`backup --keep`). Past that step the command finishes, reports
  normally and exits 0.
- Ctrl-C before the swap leaves `COPILOT_HOME` untouched; temp files and dirs
  are removed.
- A second Ctrl-C kills the process at once.
- Only a run stopped by the cancel itself prints `Aborted.`; an error from a
  step past the irreversible point (a failed rollback, a partial delete) is
  still reported as `error: …`, exit 1.

**Streams.** stdout carries results only; stderr carries prompts and notes:
every `[y/N]` prompt, `Restore which backup? [1] ` and the backup table before
it, restore's `WARNING:` block, `Backups to remove …` and its table, `clean
-q`'s summary line before its prompt, the
`Skipped …` notes, `Dry run: nothing deleted.` and `Aborted.`.

**`-q/--quiet`** prints only machine-usable results, one per line, and nothing
else on stdout (`list`: IDs; `clean`: the deleted IDs; `backup`: the created
path). Notes and prompts still appear on stderr.

**Confirmation helper.** If `--yes` is set, continue. If stdin is not a
terminal (a pipe, a file, or `/dev/null`, which counts as no TTY),
fail with `confirmation required; rerun with --yes`. Otherwise prompt
`<question> [y/N] ` (stderr) and accept only `y` or `yes` (case-insensitive).

### 6.1 `list` (alias `ls`)

```
copilot-sessions list [ID...] [filters] [--json] [-q|--quiet]
```

Sort by `updated` ascending; unknown `updated` sorts first.

**Default output:**

```
  UPDATED           STATUS            SIZE  ID                                    NAME
  2026-11-05 20:55  closed            5.5M  1bc3dfe6-2516-4792-a3fd-f60df14c3b66  Review Copilot Settings Improvement
  2026-11-06 07:03  ongoing (busy)    4.5M  354b527d-04cd-44f6-9e71-3ed055fb1daf  Create Copilot Session Manager (this session)
2 of 61 sessions (1 ongoing, 1 closed), 10.0M.
```

- Row format: 2 spaces, then `UPDATED` (local time `YYYY-MM-DD HH:MM`, or
  `unknown`) left-padded to width 16. Then 2 spaces and `STATUS` left-aligned
  to width 14 (`ongoing (busy)`, `ongoing (idle)`, `stale`, `closed`). Then 2
  spaces and `SIZE` right-aligned to width 6 (`-` for DB-only). Then 2 spaces,
  `ID`, 2 spaces, and `NAME` truncated to 60 characters (runes).
- Suffixes after the name: ` (this session)` if current, ` (db only)` if DB-only.
- Summary line: `<selected> of <total> sessions (<counts>), <total size>.`
  Counts appear in the order ongoing, stale, closed; zero counts are omitted.
- No match: `No sessions match.`

**`-q`:** print only IDs, one per line, sorted the same way. Do not compute sizes.

**`--json`:** print a JSON array with 2-space indent, sorted the same way.
Sizes are always computed. `--json` with `-q` is a usage error (exit 2):
`--json cannot be combined with --quiet`.

```json
{
  "id": "354b527d-...",
  "name": "Create Copilot Session Manager",
  "cwd": "/home/nka/Projects/personal/wsl-config",
  "updated_at": "2026-11-06T06:03:45.981000+00:00",
  "status": "ongoing",
  "busy": true,
  "current": true,
  "size": 4753254,
  "db_only": false
}
```

`busy` is `null` unless status is `ongoing`. `updated_at` is RFC 3339 in UTC or
`null`, with Go's fractional-second format (`2026-11-06T06:03:45.981Z`).

**Human-readable sizes:** use base 1024 and units `B`, `K`, `M`, `G`. Stop at
`G`. Bytes print as an integer (`375B`). Other units print with one decimal
(`2.4K`, `194.0M`).

### 6.2 `clean` (alias `rm`)

```
copilot-sessions clean [ID...] [filters] [--include-ongoing] [-n] [-y] [-q]
copilot-sessions clean -a|--all            [--include-ongoing] [-n] [-y] [-q]
```

| Flag | Meaning |
|------|---------|
| `-a, --all` | select all sessions |
| `--include-ongoing` | also delete ongoing sessions |
| `-n, --dry-run` | show the selection, delete nothing |
| `-y, --yes` | skip confirmation |
| `-q, --quiet` | print only the IDs of the deleted sessions (with `-n`: that would be deleted); do not compute sizes |

Validation (usage error, exit 2):

- `--all` with any ID or filter: `--all cannot be combined with IDs or filters`
- No `--all`, no ID and no filter:
  `specify session IDs, a filter (--until, --since, --status, --cwd, --grep, --empty) or --all`

Selection and safety rules, in this order:

1. Apply the filters (5.2).
2. Always remove the **current** session from the selection. Print
   `Skipped this session (it runs this command).` (stderr)
3. Remove `ongoing` sessions unless `--include-ongoing` is set or `--status`
   contains `ongoing`. Print
   `Skipped <N> ongoing session(s) (use --include-ongoing).` (stderr; section 6.5
   shows the plural rule.)
4. If nothing remains, print `No sessions match.` (not with `-q`) and exit 0.

Output: the skip notes (stderr), then the table and the summary line. With
`-q` neither goes to stdout; when the confirmation prompt will be shown (no
`-y`, no `-n`, stdin is a TTY), the summary line, without its size part, goes to
stderr before it:

`<N> of <total> sessions selected (<scope>[, <size>]).`

`<scope>` is `all sessions` for `--all`. Otherwise it is the active filters
joined with `; `, in this order:

- `IDs <a>, <b>`
- `updated on or after <date>`
- `updated on or before <date>`
- `status <statuses sorted, joined with '/'>`
- `cwd under <path as given>`
- `name contains '<text>'`
- `empty`

- With `-n`: with `-q`, print the selected IDs; print `Dry run: nothing
  deleted.` (stderr) and exit.
- Otherwise ask `Permanently delete these sessions?`. On no, print `Aborted.`
  (stderr).

Deletion steps:

1. Remove each selected session directory recursively.
2. In one SQLite transaction, delete rows `WHERE session_id IN (<ids>)` from
   each of these tables **if it exists**: `search_index` (an FTS5 table),
   `turns`, `checkpoints`, `session_files`, `session_refs`,
   `forge_trajectory_events`, `assistant_usage_events`. Then delete from
   `sessions WHERE id IN (<ids>)`. Use a busy timeout of 30 s, because Copilot
   may have the DB open. Use a temp table or bound parameters; never build SQL
   from IDs without escaping.
3. Update the UI state:
   - `open-sessions-state.json`: remove the deleted IDs as keys.
   - `sidebar-sessions-state/*.json`: remove the deleted IDs from `sessionIds`.
   - If the deleted set equals **all** known sessions, clear both completely:
     `{}` and `"sessionIds": []`.
   - Write a file only if it changed. Write it atomically: write a temp file,
     keep the original file mode, rename. Use 2-space indent and a trailing
     newline. Keep all other keys. Do not escape HTML characters.
4. Print `Deleted <N> session(s).`, or with `-q` the deleted IDs, one per line.

### 6.3 `backup`

```
copilot-sessions backup [FILE] [-k N] [-y] [-q]
copilot-sessions backup -l|--list [--json]
copilot-sessions backup -k N --no-create [-y]
```

| Flag | Meaning |
|------|---------|
| `FILE` | output path (default: `$COPILOT_BACKUP_DIR/copilot-sessions-YYYYmmdd-HHMMSS.tar.gz`, local time) |
| `-l, --list` | list backups in the backup dir, newest first |
| `-k, --keep N` | after the backup, keep only the newest N backups in the backup dir |
| `--no-create` | with `--keep`: only delete old backups |
| `-y, --yes` | skip confirmation for deleting old backups |
| `--json` | with `--list`: JSON output |
| `-q, --quiet` | print only the created backup path |

Validation (usage error, exit 2):

- `--list` with FILE, `--keep` or `--no-create`: `--list cannot be combined with FILE, --keep or --no-create`
- `--json` without `--list`: `--json only works with --list`
- `--no-create` without `--keep`: `--no-create requires --keep N`
- `--keep` < 1: `--keep must be at least 1`

**Archive format.** This must stay compatible with backups made by the Python
version, in both directions.

- gzip-compressed tar, file mode `0600`. Create parent directories.
- Top-level entries, each only if it exists:
  - `session-state/` (recursive)
  - `session-store.db`
  - `open-sessions-state.json`
  - `sidebar-sessions-state/` (recursive)
- Exclude `session-state/.session-operation-locks` and everything below it.
- `session-store.db` in the archive is a **consistent snapshot**. Take it with
  the SQLite online backup API or `VACUUM INTO` into a temp file. Do not copy
  the file: WAL content would be lost. Never include the `-wal` or `-shm` files.
- Keep file modes and mtimes in the tar headers.

Output: `Backup created: <path> (<N> session(s), <size>)`. With `-q`, only the
path. `<N>` counts the session directories.

**Retention (`--keep N`).** Only files that match `copilot-sessions-*.tar.gz`
in the backup dir count. Sort by file name, newest first. Old backups are all
backups after the first N.

- If there are none: `Nothing to remove: at most <N> backups in <dir>.`
  (not shown with `-q`).
- Otherwise, when the prompt will be shown (no `-y`, stdin is a TTY), print
  `Backups to remove (keeping the newest <N>):` and the backup table to stderr.
  Ask `Delete <N> old backup(s)?` (on no, `Aborted.` on stderr), delete, and
  print `Deleted <N> old backup(s).` (not with `-q`).

**Backup table (`--list`):**

```
   #  CREATED             SIZE  FILE
   1  2026-11-06 13:46   50.3M  /home/nka/.copilot-backups/copilot-sessions-20261106-134624.tar.gz
```

`CREATED` comes from the timestamp in the file name. If that does not parse,
use the file mtime. With no backups, print `No backups in <dir>`.
JSON: `[{"file": "<path>", "created": "<RFC 3339 local>", "size": <bytes>}]`.
`created` has a numeric offset and no sub-second part, `+00:00` (never `Z`) in
UTC: `2026-10-31T12:00:00+02:00`.

**Deliberate departures from the script.**

- The archive is written to a hidden temp file (`.copilot-sessions-*.tmp`) in the
  target's directory and moved into place only when complete. A failed backup
  leaves nothing that `--list`, `--keep` or `restore latest` could pick.
- A default-named backup never overwrites an existing file; a second backup in
  the same second fails with `backup already exists: <path>`. An explicit
  `FILE` is still overwritten.
- Entries that vanish while the backup runs are skipped. A file that shrinks
  after it was stat-ed is padded with zeros to its stat-ed size, as GNU tar does.
  Any other read error (for example a permission error on a top-level item)
  fails the backup.
- A missing backup directory is created with mode 0700, like `COPILOT_HOME`.
- Only `.session-operation-locks` itself is excluded; siblings such as
  `.session-operation-locks-old/` are archived.
- If the session count cannot be read after the archive is written, the backup
  is still reported (`Backup created: <path> (<size>)`) after a `warning:` on
  stderr, and `--keep` still runs.

### 6.4 `restore`

```
copilot-sessions restore [FILE|latest] [-y]
```

- `latest` means the newest backup in the backup dir.
- With no argument and a TTY on stdin, print the backup table and prompt
  `Restore which backup? [1] ` (both stderr). An empty answer means 1. An invalid answer
  fails with `invalid choice '<x>'`.
- With no argument and no TTY, fail with `no backup given; pass FILE or 'latest'`.
- Errors: `no backups in <dir>`, `backup not found: <path>`, and
  `<path> does not look like a copilot-sessions backup` (the archive has
  neither `session-state` nor `session-store.db`).

Before restoring, print this warning to stderr and ask `Continue?` (on no,
`Aborted.` on stderr):

```
WARNING: restore REPLACES all current Copilot sessions.
  Backup:  <path> (<N> session(s))
  Current: <COPILOT_HOME> (<M> session(s) will be deleted)
  Close all running Copilot CLI sessions first; they may overwrite restored data.
```

`<N>` is the number of distinct non-hidden names directly below `session-state/`
in the archive.

Restore steps:

1. Extract into a temp directory **inside** `COPILOT_HOME`, so that renames
   stay on the same file system.
2. Extract safely. Reject absolute paths, `..` components, symlinks or hard
   links that point outside the target, and device, FIFO or other special
   files. Remove setuid and setgid bits. This matches Python
   `tarfile` `filter="data"`, with three deliberate departures: a symlink target
   must point downward (no absolute path, no `..`), none of the four top-level
   items may be a symlink, and a missing `COPILOT_HOME` is created instead of
   failing.
3. For each of the four top-level items: move the current item (for
   `session-store.db`, also `session-store.db-wal` and `session-store.db-shm`)
   aside into the temp directory, then rename the extracted item into place if
   it exists in the archive. Deliberate departure from the script, which deletes
   first: if any rename fails, every move is undone and the restore fails with
   `restore failed, nothing changed: <err>`, leaving `COPILOT_HOME` unchanged. If
   the rollback itself fails, the temp directory is kept and the error names it
   (`restore failed and rollback incomplete; old data kept in <dir>: <err>`). On
   success the temp directory, with the old items, is removed.
4. Print `Restored <N> session(s) from <path>`.

### 6.5 Plurals

`<n> <word>` gets an `s` unless n == 1: `1 session`, `2 sessions`,
`1 old backup`.

## 7. Help text

Root description: `List, clean, back up and restore GitHub Copilot CLI sessions.`

The root help must also mention:

- the DATE formats
- the current values of `COPILOT_HOME` and `COPILOT_BACKUP_DIR`, with the

Port the per-flag help strings from the Python script, except `-q` (6.1–6.3).

## 8. Shell completion

Use cobra's generated completion:
`copilot-sessions completion zsh > ~/.zsh/completions/_copilot-sessions`.
`~/.zshrc` already has `fpath=(~/.zsh/completions $fpath)` before `compinit`.
Bash and fish come from cobra for free; do not test them.

Dynamic completions:

| Target | Values |
|--------|--------|
| positional ID (`list`, `clean`) | session IDs. Description: `<status> <name or '-'>`. Get them in-process, without sizes. |
| `--status` | `ongoing`, `stale`, `closed`. Support comma lists: after `closed,`, suggest `closed,ongoing` and `closed,stale`, and do not add a space (`ShellCompDirectiveNoSpace`). |
| `--until`, `--since` | `today`, `yesterday`, `7d`, `2w`, `1m`, `3m`, with descriptions (`7 days ago`, ...). Free text stays allowed. |
| `--cwd` | directories (`ShellCompDirectiveFilterDirs`) |
| `--grep`, `--keep` | no completion (`ShellCompDirectiveNoFileComp`) |
| `restore` argument | `latest`, then the full paths of backups in the backup dir (newest first), then `*.tar.gz` files |
| `backup` FILE | files with the `tar.gz` extension |

## 9. Tests

Write table-driven tests with `go test ./...`. Tests must never touch the
real `~/.copilot` or `~/.copilot-backups`: always set `COPILOT_HOME` and
`COPILOT_BACKUP_DIR` to `t.TempDir()`.

Create the fixture in code. It needs:

- A `session-store.db` with the real schema. Section 10 lists the relevant
  tables; include FTS5 `search_index`, and enable WAL mode.
- Session directories with `workspace.yaml` and some `events.jsonl`, covering:
  - a titled session with user messages and DB turns
  - an empty session with no `events.jsonl`
  - an empty session whose `events.jsonl` has only `session.start` and `session.shutdown`
  - a stale session (`inuse.999999999.lock`)
  - an ongoing session: the lock PID is a running helper process whose
    cmdline contains `copilot`, for example a copied `sleep` binary named
    `copilot-test`
  - a DB-only session
  - sessions in different `cwd`s and on different dates
- `session-state/.session-operation-locks/x.lock`
- `open-sessions-state.json` and `sidebar-sessions-state/a.json`

Required cases:

1. DATE parsing: all formats, the month-end clamp, invalid input.
2. Status detection: ongoing, stale and closed; hidden directories are not sessions.
3. Each filter alone, AND combinations, and ID prefix errors (none, ambiguous).
4. `list` output: header, row format, summary counts, `-q`, `--json`;
   `--json -q` is a usage error.
5. `clean` validation errors; `--all` vs filters.
6. `clean` skips ongoing sessions by default and with `--status closed`, and
   includes them with `--include-ongoing` or `--status ongoing`.
7. `clean` never deletes the current session. Test this by injecting the
   ancestor-PID provider.
8. `clean` deletion: directories gone; DB rows gone from all listed tables
   (including FTS search); UI state pruned; other keys and file mode kept;
   full clear when all sessions are deleted.
9. `clean -n` changes nothing. `clean` without `--yes` and without a TTY fails.
10. `backup`: archive entries, lock dir excluded, DB snapshot includes data
    still in the WAL, mode 0600, retention with `--keep` and `--no-create`,
    `--list --json`.
11. `restore`: full replace round trip (backup Ôćĺ clean `--all` Ôćĺ restore gives
    the same IDs and DB row counts), `-wal`/`-shm` removed, `latest`, and
    rejection of path-traversal archives.
12. Compatibility (the only Python contract left): the Go version restores an archive made by the Python
    script, and the Python script restores an archive made by the Go version.
    Make this an optional test that runs only if `python3` and the script exist.
13. Cancellation (CS-013): a cancelled `backup` or extract leaves no temp file;
    `session.Delete` runs to completion once started; `clean -y`, `restore -y`
    and `backup --keep -y` cancelled before their irreversible step change
    nothing and exit 130; Ctrl-C at a `[y/N]` prompt aborts at once.
14. Permission errors (CS-013): an untraversable `COPILOT_HOME` and a backup in an
    unreadable directory are reported as errors, not as no sessions or "backup
    not found".

Make the TTY check, the stdin reader, the clock ("today") and the
ancestor-PID lookup injectable, so the tests are deterministic.

## 10. Relevant DB schema (read-only reference)

```sql
CREATE TABLE sessions (id TEXT PRIMARY KEY, cwd TEXT, repository TEXT, host_type TEXT,
  branch TEXT, summary TEXT, created_at TEXT, updated_at TEXT);
CREATE TABLE turns (id INTEGER PRIMARY KEY AUTOINCREMENT, session_id TEXT NOT NULL REFERENCES sessions(id),
  turn_index INTEGER NOT NULL, user_message TEXT, assistant_response TEXT, timestamp TEXT,
  UNIQUE(session_id, turn_index));
CREATE TABLE checkpoints (... session_id TEXT NOT NULL REFERENCES sessions(id) ...);
CREATE TABLE session_files (... session_id TEXT NOT NULL REFERENCES sessions(id) ...);
CREATE TABLE session_refs (... session_id TEXT NOT NULL REFERENCES sessions(id) ...);
CREATE TABLE forge_trajectory_events (... session_id TEXT NOT NULL REFERENCES sessions(id) ...);
CREATE TABLE assistant_usage_events (... session_id TEXT NOT NULL REFERENCES sessions(id) ...);
CREATE VIRTUAL TABLE search_index USING fts5(content, session_id UNINDEXED,
  source_type UNINDEXED, source_id UNINDEXED);
```

Leave the other tables untouched: `forge_skill_proposals`,
`dynamic_context_items` and `schema_version`. Copilot owns this schema and can
change it. Look up tables in `sqlite_master` before you delete from them, and
never create or migrate tables.

## 11. Intended differences from the Python version

- Completion is generated by cobra, not written by hand.
- Cobra adds `completion` and `help` subcommands. Usage error messages may
  follow cobra's format, but they must keep the texts from section 5 and exit
  code 2.
- Go/Cobra conventions (CS-012):
  - A bare `copilot-sessions` prints help and exits 0 (Python: usage error).
  - Unknown commands get Cobra's message with `Did you mean this?`, exit 2.
  - The flag-combination checks of `clean` and `backup` exit 2, not 1, with
    the same messages.
  - `Short` help strings are capitalised; each command has examples.
  - Prompts and notes go to stderr (section 6 *Streams*); results stay on stdout.
  - `-q` prints only IDs or paths: `clean -q` prints the deleted IDs instead of
    the summary; `backup -q --keep` prints no rotation messages on stdout.
  - `list --json -q` is a usage error; `--json` always computes sizes.
  - `--since` has no `-S` shorthand.
- Go idioms (CS-013):
  - Error texts quote values Go-style (`invalid date "x"`, not `'x'`), and so
    does `clean`'s summary (`name contains "bug"`).
  - Permission and I/O errors on `COPILOT_HOME`, `session-store.db` or a backup
    file are reported, not read as absent (no sessions, no DB, "backup not
    found").
  - `backup --list --json` `created` is RFC 3339 with a numeric offset (§6.3),
    not Python's naive `isoformat`.
  - Ctrl-C aborts prompts at once, and is honoured before irreversible steps only
    (§6).
  - Stdin of `/dev/null` is not a TTY, so a prompt without `-y` fails with
    `confirmation required` (Python: prompts, reads EOF, prints `Aborted.`).
  - The backup directory is created with mode 0700, not 0755.

The archive format stays compatible both ways (§9 case 12); flags and aliases
are unchanged.

## 12. Out of scope

- Merging restores (restore always replaces).
- Pruning `logs/`.
- Automatic backup before `clean` or `restore`.
- Windows and macOS support.

- `go fix -diff ./...` is clean.
